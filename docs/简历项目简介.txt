电商智能客服系统（Multi-Agent AI Customer Service）

================================================================================
一、项目概述
================================================================================

基于 LangGraph 构建的多 Agent 协作式电商智能客服系统，模拟真实客服场景中的
"意图识别 → 知识检索/工具调用 → 回复生成"完整闭环。系统由 5 个专业化 Agent
协作完成，涵盖意图路由、RAG 知识库检索、Function Calling 工具调用、工单升级
及自然语言回复合成全流程。支持 Web UI / CLI / REST API 三种交互模式，
Docker Compose 一键部署。

核心理念：不是简单匹配关键词，而是像真人客服一样「思考」——真正理解用户意图，
分配合适的 Agent 处理，最终给出有依据的回复。

================================================================================
二、技术栈
================================================================================

后端：Python 3.13 · LangGraph · FastAPI · Uvicorn · Pydantic
前端：Next.js 16 · React 19 · TypeScript · Tailwind CSS v4
LLM：DeepSeek（OpenAI 兼容 API）
工程化：Docker Compose · SSE 流式推送 · 多阶段构建
核心技术：RAG 检索 · Function Calling · StateGraph 状态机 · 策略模式

================================================================================
三、系统架构
================================================================================

用户输入 → Router Agent（意图分类）
               │
     ┌─────────┼──────────┐
     ▼         ▼          ▼
Knowledge   Tool    Escalation
 (RAG检索)  (函数调用)  (工单升级)
     │         │          │
     └─────────┼──────────┘
               ▼
         Summary Agent（整合回复）

- Router：意图分类，输出 order_query / product_inquiry / complaint / general
- Knowledge：RAG 知识库检索，找到相关文档后用 LLM 合成回答
- Tool：Function Calling，调用订单查询/物流追踪等工具函数
- Escalation：投诉类问题生成结构化工单转人工处理
- Summary：汇总所有 Agent 信息，生成自然语言回复

================================================================================
四、个人贡献与核心亮点
================================================================================

1. 多 Agent 协作架构设计
   基于 LangGraph StateGraph 编排 5 个专用 Agent，通过 add_conditional_edges
   条件边实现动态意图路由。设计 AgentState（TypedDict）共享状态，采用累加而非
   替换的策略传递 thought_chain，确保 Agent 思考链完整可追溯，前端可逐步展示
   每个 Agent 的处理过程。

2. RAG 知识库检索
   对 9 篇中文产品文档（FAQ、退换货政策、配送说明等）进行分块处理，自研轻量级
   关键词检索方案：中英文混合分词（中文按单字、英文按空格）+ Jaccard 相似度
   计算取 top-3 文档块送入 LLM 合成。零外部向量数据库依赖，零额外服务部署。

3. Function Calling 工具集成
   基于 OpenAI 兼容 tools API 设计 4 个业务工具函数（query_order / track_
   shipment / check_return_policy / get_product_info），LLM 自动判断调用哪个
   工具并提取参数，业务逻辑由代码执行。工具接口标准化设计，可无缝对接真实
   数据库或第三方 API。

4. SSE 流式推送与思维链可视化
   基于 FastAPI StreamingResponse 实现 Server-Sent Events 实时推送，前端设计
   AgentThoughtChain 组件：折叠态显示彩色状态圆点（绿=完成/黄=运行/红=报错），
   展开后按时间顺序展示每个 Agent 的处理详情。让用户看到 AI 推理过程而非黑盒
   回答，提升系统透明度和信任感。

5. 可插拔数据源架构
   抽象 ECommerceDataProvider 接口（ABC + 策略模式），通过环境变量动态导入
   Provider 实现，演示数据与真实数据库零代码切换。预置 3 个示例订单和 3 个
   产品数据，架构上完全支持对接真实电商后台。

6. 全栈工程化交付
   后端 FastAPI + 前端 Next.js 16 standalone 模式 + Docker Compose 编排部署。
   前端多阶段构建优化镜像体积，Next.js rewrites 反向代理解决跨域与端口暴露。
   后端健康检查 + 前端依赖等待机制，确保服务有序启动。支持 Web UI / CLI /
   REST API 三种交互模式，含完整使用手册与数据接入文档。

7. 多层错误兜底机制
   LLM 调用失败返回友好中文提示；工具函数异常时 LLM 引导用户；前端 API 调用
   失败显示错误消息而非白屏；所有 Agent 均有降级回复逻辑，确保单点异常不影响
   整体对话流程。
